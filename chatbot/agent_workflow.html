DMS Chatbot Agent Workflow

This view shows how a question enters the backend, gets classified into a task, routes to the right agent, and then returns either JSON or SSE with chat logging.

1. Request EntryFrontend sends POST /api/chatbot/agent-chat with question, chat_id, and stream flag.
→
2. Selected Documents?If documents are included, the backend uses the older /api/chatbot/chat path.
Main Agent Path
3. Intent ClassificationIntentClassifier.classify builds search hints and asks the LLM to choose the task.
→
4. Clean Debug LogBackend prints one clear line: Task classification result with intent, confidence, source, and parameters.
5. Stream Mode?Non-stream requests go to orchestrate_agent_chat. Stream requests go to _build_agent_stream.
6A. keyword_searchUses exact phrase or must-term search through _execute_raw_search or _execute_search.
6B. semantic_searchUses hybrid retrieval in OpenSearch to find similar documents.
6C. stats_countRuns an OpenSearch count-style query using date and topic constraints.
6D. single_doc_summaryLoads one document by ID and asks the LLM for a short summary.
6E. mixed_search_summaryFinds relevant documents first, then asks the LLM to summarize them together.
6F. general_rag_qaMain chatbot flow: retrieve relevant documents, build RAG context, then answer with the LLM.
7. Retrieval and Answeringgeneral_rag_qa uses SemanticSearchAgent, _build_rag_context, and then _generate_completion or _generate_completion_stream.
→
8. Save Chat LogMessages, response, and token usage are saved to the chat_logs_dms index in OpenSearch.
→
9. Return ResultThe backend returns either JSON or SSE stream back to the frontend, including the chosen intent.
Classification: IntentClassifier
Main chatbot path: general_rag_qa
Retrieval: OpenSearch hybrid search
Answering: LLM completion or stream
