1. Scope and Access

  • This guide is restricted to users with System Administrator privileges.
  • Admin-level modules include: System Administration, User Management, System Auditing, and Reports.
  • Only administrators should change scheduler jobs, code tables, and infrastructure configuration.

2. What System Administrators Can Configure

2.1 Access and Identity

  • Create and maintain users and groups.
  • Assign functional permissions per module.
  • Map folder-level access controls (read/write/delete).

2.2 System Administration Module

  • Retention Management: policy windows, retention periods, and disposition schedules.
  • Reminder Management: reminder offsets and trigger timings.
  • Job Management: background schedules and execution behavior.
  • Code Table Management: configurable business lookup values.

2.3 Environment-Level Configuration

  • Backend server port (SERVER_PORT).
  • Database connection and credentials (SPRING_DATASOURCE_*).
  • OpenSearch endpoint and credentials (app.opensearch.* properties).
  • CORS allow list (APP_CORS_ALLOWED_ORIGINS).
  • Optional AI/OCR integrations (DEEPSEEK_*, DOTSOCR_*, EXTRACTION_API_*).

3. Installation Prerequisites

  • Windows 10/11 (or equivalent Linux/macOS environment).
  • Node.js 20.19+ and npm 10+.
  • Java JDK 21.
  • MySQL 8+ (local or remote).
  • OpenSearch (default endpoint: https://localhost:9200).
  • Network access for any optional AI/OCR services used by your deployment.
Keep service credentials and encryption keys in secured environment variables. Do not commit secrets to source control.

4. Installation Steps

Step 1: Prepare the Workspace

  1. Open a terminal in the project workspace root.
  2. Confirm the folders exist: backend and frontend.

Step 2: Configure Backend Properties

  1. Open backend/src/main/resources/application.properties.
  2. Set or override database and service values for your environment.
  3. Recommended: use environment variables for secrets and per-environment values.
SPRING_DATASOURCE_URL=jdbc:mysql://localhost:3306/dms?createDatabaseIfNotExist=true&useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC
SPRING_DATASOURCE_USERNAME=root
SPRING_DATASOURCE_PASSWORD=******
APP_CORS_ALLOWED_ORIGINS=http://localhost:5173
SERVER_PORT=8080

Step 3: Start MySQL

  1. Start your MySQL server service or container.
  2. Create database dms if it is not auto-created by your JDBC URL.
  3. Verify connectivity with the configured user/password.

Step 4: Start OpenSearch

  1. Start OpenSearch with HTTPS enabled if using default backend settings.
  2. Confirm endpoint/credentials match backend config:
app.opensearch.host=localhost
app.opensearch.port=9200
app.opensearch.username=admin
app.opensearch.password=<password>
app.opensearch.https=true

Step 5: Build and Start Backend

  1. Open terminal in backend.
  2. Run:
./mvnw spring-boot:run

On Windows PowerShell, use .\mvnw.cmd spring-boot:run.

Step 6: Install and Start Frontend

  1. Open terminal in frontend.
  2. Run:
npm install
npm run dev

Default frontend URL: http://localhost:5173.

5. Client Workstation Scanner Bridge Deployment

5.1 Purpose

The Node Scanner Bridge runs on each client workstation and exposes local scanner operations to the Automated Smart ECM frontend. Default local endpoint: http://localhost:8787.

5.2 Prerequisites (Client Workstation)

  • Windows workstation with scanner connected by USB.
  • Scanner driver installed and verified in Windows.
  • Node.js 18+ installed (Node.js 20 LTS recommended for consistency).
  • Access to folder DMS/tools/node-scanner-bridge.

5.3 Install Steps

  1. Open PowerShell on the client workstation.
  2. Navigate to the scanner bridge folder:
cd DMS/tools/node-scanner-bridge
  1. Install dependencies:
npm install
  1. Start the service:
npm start

5.4 Validation Steps

  1. Confirm health endpoint returns success:
Invoke-WebRequest http://localhost:8787/health -UseBasicParsing
  1. Confirm scanner enumeration returns devices:
Invoke-WebRequest http://localhost:8787/scanners -UseBasicParsing
  1. Open the Automated Smart ECM upload panel and click Scan to verify the workstation scanner appears.

5.5 Auto-start at User Logon (Recommended)

Create a Task Scheduler task on each scanner workstation:

  1. Task Scheduler - Create Task.
  2. Trigger: At log on for the workstation user.
  3. Action: Start a program using powershell.exe.
  4. Arguments example:
-NoProfile -ExecutionPolicy Bypass -Command "cd 'D:\\POC\\DMS2\\DMS\\tools\\node-scanner-bridge'; npm start"
  1. Save task and run it once to confirm the bridge comes up on port 8787.

5.6 Operational Notes

  • Keep the bridge local to workstation (localhost); do not expose it externally.
  • If multiple scanner users share one PC, run bridge under the active desktop user session.
  • If the bridge fails to enumerate scanners, reinstall/update scanner driver and restart bridge.
  • Supported API endpoints: GET /health, GET /scanners, POST /scan.

6. Startup and Verification

  1. Start MySQL.
  2. Start OpenSearch.
  3. Start backend and wait for Tomcat started on port 8080.
  4. Start frontend and verify Vite reports local URL.
  5. Open the application and sign in with an administrator account.
# Quick checks
http://localhost:8080
http://localhost:5173

7. Post-Installation Checklist

  • Confirm role-based access is enforced by logging in as non-admin and admin users.
  • Verify document upload, versioning, and folder permission behavior.
  • Verify OpenSearch-backed features (search, indexing, and relevant modules).
  • Review scheduler entries and ensure expected jobs are enabled.
  • Set backup/restore plans for MySQL and OpenSearch data.

8. Operational Administration Tasks

8.1 Routine Tasks

  • Onboard/offboard users and maintain group membership.
  • Review audit logs for security and compliance checks.
  • Maintain code tables and business reference values.
  • Review reminder and retention execution results.

8.2 Change Management

  • Apply configuration changes in lower environments first.
  • Capture before/after values for each admin-level setting update.
  • Schedule high-impact changes during maintenance windows.

9. Troubleshooting

  • Backend fails on startup: verify MySQL/OpenSearch availability, URLs, credentials, and ports.
  • Login or authorization issues: verify role mappings and function permissions.
  • Search/index issues: verify OpenSearch endpoint and index permissions.
  • CORS errors in browser: update APP_CORS_ALLOWED_ORIGINS for frontend origin.
  • File operation failures: validate user permissions and payload size constraints.
  • Scanner not detected: confirm bridge is running on http://localhost:8787, scanner driver is installed, and /scanners returns devices.
If a production incident occurs, preserve logs and configuration snapshots before applying emergency fixes.
